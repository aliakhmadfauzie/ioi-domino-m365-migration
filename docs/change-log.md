## Change Log Guidelines

### When to Add an Entry
1. **File created** — New documentation, analysis, or design file
2. **File modified** — Content changed in a significant way
3. **File deleted** — File removed or deprecated
4. **Milestone reached** — Phase or task completed
5. **Decision made** — Recorded in decision log
6. **Bug fixed** — Significant bug fix in app or design
7. **Data changed** — Field mapping, migration rules, or schema changed

### How to Format an Entry
```
| {YYYY-MM-DD} | {Author} | {Brief description} | {File paths} | {Reason or trigger} |
```

### Related Logs
- **Decision Log**: `docs/decision-log.md` — for business/design decisions
- **RAQ Log**: `docs/risks-assumptions-questions.md` — for risks, assumptions, questions
